# AI Ad Agent: самообучаемый по метрикам

Прототип агента, который запускает и ведет рекламу как толковый маркетолог: следит за ценой
клика, заявки и показа, смотрит конверсии и **сам подкручивает ставки и бюджет, чтобы выходило
выгоднее**. Самооптимизация идет по метрикам, без ручной разметки и участия LLM.

Площадка для демо это честный **мок-аукцион второй цены с конкурентом**. Архитектура заточена так,
что **подключить реальную площадку значит написать один адаптер**.

---

## Что видно в демо

Сценарий: 5 креативов с разным скрытым качеством (агент их не видит), цель CPA $15. За 50–100 тиков
агент сам приходит к экономически верной раскладке и **держит три разных режима одновременно**:

- **B «бесплатно 7 дней» и C «видео-демо»** — прибыльные «звёзды»: CPA ниже цели даже на потолке
  ставки, агент жмёт ставку вверх и переливает на них бюджет;
- **D «отзыв клиента»** — маржинальный: агент находит **промежуточную ставку (~$1.8)**, на которой
  CPA садится прямо у цели. Это и есть видимая «толковость» контроллера, а не просто потолок;
- **A «скидка» и E «новинка»** — убыточные при этой цели: агент набирает статзначимость и **ставит
  их на паузу** (E с CPA ~$22 — явный «дог»).

Общий **CPA держится заметно ниже цели ($6–7 при цели $15), ROAS ~8**. Прогон детерминирован (seed).

## Запуск

```bash
npm install
npm run dev         # дашборд: http://localhost:3000
```

Без ключей все работает: математика и оптимизация не зависят от LLM. Если положить
`ANTHROPIC_API_KEY` в `.env`, человекочитаемый разбор решений будет писать Claude (иначе шаблон).

Проверка ядра без UI (видно раскладку «звёзды на потолке / маржинальный у цели / убыточные в паузе»):

```bash
npm run sim 140
```

Юнит-тесты на математику (метрики, аллокация, контроллер ставки, guardrails, экономика аукциона):

```bash
npm test
```

## Что потыкать в дашборде

- **▶ Старт**: агент начнет тикать. Первые ~10-20 тиков идет разведка (CPA скачет, заявок мало),
  дальше раскладка устаканивается.
- **Таблица «Креативы»**: видно, как **B** и **C** уезжают в потолок ставки $5, **D** садится на
  промежуточную ставку (ниже потолка) и держит CPA у цели (это «дышащая» работа контроллера), а
  **A** и **E** уходят в паузу. Колонка **«Доля»** показывает, как бандит переливает бюджет на
  лучших. У паузных рук в таблице остаются цифры, по которым их выключили (CPA выше порога).
- **График CPA/ROAS**: CPA держится у/ниже пунктира target ($15), ROAS около ~7-8 (метрики за
  скользящее окно, это «свежее» состояние кампаний, а не растущий лайфтайм-итог).
- **Слайдер Target CPA**: двигай вживую. На $8 агент жестче (порог паузы ниже, выключает больше),
  на $30 мягче (почти все живут). Влияет на будущие решения; **уже выключенные руки назад не
  включаются** (раз отбраковали по статзначимости, не дергаем; для перезапуска сценария жми **↻ Сброс**).
- **Скорость**: ускорь, чтобы быстрее увидеть сходимость; **Шаг**: прогнать один тик вручную.
- **«Решения агента»**: лог с обоснованиями каждого решения (без `ANTHROPIC_API_KEY` шаблон; с
  ключом разбор пишет Claude, его зовем каждый 5-й тик ради экономии).

## Архитектура: контур Sense, Decide, Act

Агент это цикл, который тикает (в симуляции ускоренно):

```
  [Sense]   собрать сырые события из адаптера площадки в event store
     |
  [Decide]  два уровня решений:
              • Allocation: куда лить бюджет   (Thompson Sampling, бандит)
              • Bidding:    какую ставку держать (контроллер к target CPA)
            плюс guardrails (статзначимость, пейсинг, клампы, разведка)
     |
  [Act]     вернуть в площадку: ставки, бюджеты, пауза и запуск
     |
  [Explain] LLM пишет человекочитаемый разбор (математику не трогает)
```

### Три шва, которые делают проект масштабируемым (каждый это интерфейс)

| Шов | Файл | Смысл |
|-----|------|-------|
| `AdPlatform` | [src/platforms/AdPlatform.ts](src/platforms/AdPlatform.ts) | адаптер площадки. Новая площадка (Яндекс, Google, Meta, TG) это новый класс, остальное не трогаем |
| `Optimizer` | [src/core/optimizer/Optimizer.ts](src/core/optimizer/Optimizer.ts) | стратегия решений. Бандит сегодня, контекстный бандит или RL завтра без переписывания |
| `MetricStore` | [src/core/metrics.ts](src/core/metrics.ts) | журнал событий. Массив сегодня, Postgres дальше, Kafka или Timescale при масштабе |

## Метрики: из потока событий (event-sourcing)

Сырые события: `impression`, `click`, `spend`, `lead(value)` на каждую **руку** (это креатив внутри
кампании). Из них в окне выводим: CTR, CPC, CPM, CVR, **CPA** (главная цель), **ROAS** (вторая цель).

Почему так: события неизменяемы и аудируемы, любую метрику можно пересчитать и объяснить, откуда
цифра. Это и отличает толкового маркетолога от черного ящика.

**Забывание (скользящее окно).** Метрики считаем не за всё время, а в окне `windowHours` (по
умолчанию 48ч). Это намеренно: реклама нестационарна (усталость креатива, смена аукциона, сезон),
и контроллер со бандитом должны реагировать на **свежее** поведение, а не на размытое среднее за
всю историю. Окно простое и аудируемое; при желании за тем же интерфейсом ставится экспоненциальное
затухание (discounting). `windowHours: 0` отключает забывание (кумулятивно) — компромисс «стабильнее
апостериор, но не видит нестационарности».

## Самооптимизация: ядро

Работу маркетолога формализуем как последовательное распределение бюджета под целевой CPA и ROAS.

**1. Куда лить деньги: Thompson Sampling** ([thompson.ts](src/core/optimizer/thompson.ts)).
На каждый креатив держим Beta-апостериор по CVR: `Beta(1+conversions, 1+clicks−conversions)`.
На каждом тике сэмплим CVR, считаем ожидаемый ROAS и распределяем бюджет в пользу лучших.
Бандит сам исследует новые креативы (широкий апостериор) и эксплуатирует победителей.

**2. Какую ставку держать: демпфированный контроллер** ([bidController.ts](src/core/optimizer/bidController.ts)).
CPA ниже цели значит есть запас, поднимаем ставку и берем объем. CPA выше значит снижаем. С
ограничением скорости изменения и клампом по минимуму и максимуму. В мок-аукционе вторая цена
растет со ставкой (CPC → рыночная цена), поэтому у **прибыльных** креативов оптимум на потолке (их
жмём вверх), а у **маржинальных** — внутренний: контроллер находит ставку, на которой CPA садится
ровно у цели. Эту разницу видно в демо (D держится на ~$1.8, B/C на потолке).

**Guardrails: это и есть «толковость», а не азарт** ([BanditOptimizer.ts](src/core/optimizer/BanditOptimizer.ts)):
не убиваем креатив, пока не накоплена статистическая значимость (порог показов и кликов), пейсинг
бюджета, гарантированная разведка на старте, лимиты на ставку и скорость изменений.

## Роль LLM (Claude): намеренно НЕ оптимизатор

Деньгами рулит детерминированная математика (предсказуемо и аудируемо). Claude пишет
человекочитаемый разбор решений и дневной отчет
(«поставил на паузу E: CPA $23 при 1.5 от цели на достаточной статистике, перелил бюджет на B»).
Это разделение **«математика отвечает за деньги, LLM за язык и объяснение»** это осознанное решение.

LLM зовётся **не на каждый тик** (`llmEveryTicks`, по умолчанию каждый 5-й), между ними — дешёвый
детерминированный шаблон: в проде дёргать модель на каждом тике дорого и не нужно. Любая ошибка
сети/ключа/лимита деградирует до шаблона, агент не останавливается.

## Стек

- **Next.js 16 плюс React 19**: дашборд и API в одном приложении (App Router).
- **TypeScript end-to-end**: общие типы между симулятором, агентом, API и UI.
- **Recharts**: живые графики CPA и ROAS.
- **@anthropic-ai/sdk**: слой объяснений (опционально).

Сознательно держал прототип легким: тик-цикл на `setInterval`, event store в памяти. Это
**прячется за теми же интерфейсами**: при масштабе ядро уезжает в отдельный сервис на NestJS,
очередь становится BullMQ или Temporal, store в Postgres или Timescale, фронт остается на React.
Миграция дешевая ровно потому, что все разнесено по трем швам.
